# Deploying BloodLink

BloodLink runs as one Render web service (the API and the React app together) with a MongoDB Atlas database. The repo already contains everything Render needs: `render.yaml` describes the service, and `.node-version` pins Node 24.

Plan for about 30 minutes. You need a GitHub account; Atlas and Render accounts are free to create.

## 1. Put the code on GitHub

1. On [github.com/new](https://github.com/new), create a repository named `bloodlink`. Make it **Private**, and don't add a README, `.gitignore` or licence (the project has them).
2. In a terminal in the project folder:

   ```bash
   git remote add origin https://github.com/YOUR-USERNAME/bloodlink.git
   git push -u origin main
   ```

Your `server/.env` is not uploaded: `.gitignore` excludes it.

## 2. Create the database on MongoDB Atlas

1. Sign up at [cloud.mongodb.com](https://cloud.mongodb.com) and create a project called **BloodLink**.
2. **Create a cluster.** For a soft launch choose the **free** tier. Pick **AWS, Singapore (ap-southeast-1)**, which is next to Render's Singapore region, so the app talks to its database quickly.
3. **Database Access → Add New Database User.** Name it `bloodlink-app`, use **Autogenerate Secure Password** and copy the password somewhere safe. Give it **Read and write to any database**.
4. **Network Access → Add IP Address → Allow Access from Anywhere** (`0.0.0.0/0`). Render's free instances don't have a fixed address, so this is needed; the strong password is what protects the database.
5. **Connect → Drivers.** Copy the connection string. It looks like:

   ```
   mongodb+srv://bloodlink-app:<db_password>@cluster0.abcde.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0
   ```

   - Replace `<db_password>` with the password. If the password has symbols like `@ : / ? # %`, they must be URL-encoded; the autogenerated ones are letters and digits, which is why step 3 suggests them.
   - Add the database name **`bloodlink`** after `.mongodb.net/`, so it reads `…mongodb.net/bloodlink?retryWrites=…`

**Backups:** the free tier has no automatic backups. Before real patients and donors depend on it, move to a paid cluster with backups turned on.

## 3. Create the service on Render

1. Sign up at [render.com](https://render.com) with your GitHub account.
2. **New → Blueprint**, connect GitHub if asked, and choose the `bloodlink` repo. Render reads `render.yaml` and shows one web service called `bloodlink`.
3. Render asks for the values marked as secret in `render.yaml`:

   | Setting | What to enter |
   | --- | --- |
   | `MONGO_URI` | The Atlas connection string from step 2 (required) |
   | `MSG91_AUTH_KEY`, `MSG91_TEMPLATE_ID` | Leave empty for now (see step 5) |
   | `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | Leave empty for now (see step 5) |

   `JWT_SECRET` is generated for you. `CLIENT_URL` isn't needed: the server uses the service's own `https://….onrender.com` address automatically.
4. Click **Apply**. The first build takes a few minutes. When it finishes, the service shows **Live** and its address, like `https://bloodlink.onrender.com`.

**Never** add `OTP_DEV_SHOW_CODE` or `RATE_LIMIT` on Render. Those are for local testing only.

## 4. Check it works

1. Open `https://YOUR-APP.onrender.com/api/health`. It should show `{"ok":true}`.
2. Open the site, **Sign up** as a donor, and set your location.
3. In a private window, sign up as a second person and **post a request** for a blood group your first account can give to. The first account's dashboard should show the alert instantly.
4. Open the site on your phone. Location works because it's served over https. In the browser menu, **Add to Home Screen** installs it like an app.

The live database starts empty, which is right. **Don't run the seed scripts against it:** they're blocked from running on Atlas, and `seed:india` deletes everything first.

## 5. Turn on the optional extras

Add these in Render under **your service → Environment**. Saving redeploys automatically.

- **SMS codes (MSG91):** once your DLT template is approved, set `MSG91_AUTH_KEY` and `MSG91_TEMPLATE_ID`. Sign-up then confirms phone numbers, and "One-time code" appears on the login page. Sign up once with your own number to check a text arrives; if it doesn't, Render's **Logs** tab shows MSG91's reason.
- **Push notifications** (alerts when the app is closed): run `npm run vapid --prefix server` on your computer and copy the two keys into `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY`. Set `VAPID_EMAIL` to `mailto:` plus a real contact address.
- **Your own domain:** Render → **Settings → Custom Domains**, follow the DNS steps, then set `CLIENT_URL` to `https://your-domain`.

## 6. Before a public launch

- **Upgrade the Render instance.** Free instances sleep after 15 minutes without visitors and take about a minute to wake. That's fine for testing, not for emergencies. Change the instance type in Render's settings (or `plan` in `render.yaml`).
- **Upgrade Atlas** to a cluster with backups.
- **Finish the legal pages** in `client/src/pages/Legal.jsx` (fill in the `[placeholders]`, get them reviewed).
- **Connect MSG91** so every new account has a verified number.

## Updating the live site

Every `git push` to `main` redeploys automatically. If a build fails, Render keeps the previous version running and shows the error under **Events** and **Logs**.

## Troubleshooting

| What you see | Likely cause |
| --- | --- |
| Build fails at `npm ci` | A `package.json` changed without its `package-lock.json`. Run `npm install` in that folder locally, commit both files, push |
| Logs say `Could not connect to MongoDB` | Atlas Network Access doesn't allow `0.0.0.0/0`, the password in `MONGO_URI` is wrong or not URL-encoded, or the database user is missing |
| Logs say `Missing MONGO_URI or JWT_SECRET` | `MONGO_URI` wasn't filled in on Render |
| Site takes about a minute to load the first time | The free instance was asleep; see step 6 |
| Everyone gets "Too many requests" | Only if `TRUST_PROXY` was set to `0` on Render. Remove it; Render is detected automatically |
| "We couldn't send the code" at sign-up | MSG91 refused the text; the reason is in Render's Logs |
